# ECOLOGY — 庭の小さな命と祈り（ecology.v1）

状態: 2026-11-12 本人の方向付け（「種を蒔き、あとは運と小さな命に委ねる。祈りが魔法のように現れる時がある。
起きることが互いに関係し、予想外の庭になる」「生き物が庭の育ち方も変える」）を受けて定めた初版。
数値は初期値であり、遊んだ結果で調整する場合は版を上げて記録する（登録後の無言変更はしない）。

初版公開前の修正記録: 陰を `LightExposureQ < 800`（地図上1セル）→「岩に接する土、または減光の土」（8セル）、
光る苔を「陰かつ湿り60%以上が3つ以上」→「陰で湿り55%以上が2つ以上」に変更。720投の計測で苔・蛍・きのこが一度も
現れなかったため（地図上で条件が成立し得なかった）。

## 1. 位置づけ

- 一投の流れ: 準備 → 面の公開 → （7面目）→ 願い → 振る → **自然シミュレーション（既存・不変）** → **生態の一歩（本書）** → 保存。
- 生態の一歩は既存シミュレーションの**後**に独立して走る。既存の `Simulation.Resolve` と参照照合テストは変えない。
- 生態の偶然は、振る時に保存する `DrawEntropyCommitted.ecologyBase64`（64 bytes）**だけ**から引く。保存してから解釈する原則は他と同じ。
- 結果（新しい種、成長の上乗せ、訪れた生き物）は `Resolved.postState` と `Resolved.ecology` に保存する。再開時は保存済みの状態を読むだけで、再計算しない。
- 水は動かさない（水収支 0 の検証は既存のまま有効）。生き物は**種を運ぶ**ことと**成長を少し助ける**ことだけを行う。

## 2. 用語（すべて一投後の庭の状態から決まる）

| 語 | 定義 |
| --- | --- |
| 花 | 段階が Flower の植物 |
| 湿った土 | 土のあるセルで `SoilWater × 100 / SoilCapacity ≥ 60` |
| 陰（岩陰） | 岩（Solid）に上下左右で接する土、または `LightExposureQ < 1000` の土（地図上 8 セル） |

| 空き地 | `Plantable = 1` で植物の無いセル |
| 直近の恵み | 今回を含む直近7投で出た恵みの系統 |

## 4. 偶然の引き方

`EntropyBuffer(ecologyBase64)` を 1→2→9→10 の順に使う（確率判定は `UniformBelow(n) == 0`、候補選びは `UniformBelow(候補数)`、候補はセル番号順）。
使い切った場合は、残りの判定を「起きない」とし、`ecology.exhausted = true` を記録する（欠測は欠測のまま）。

## 5. 見せ方の原則

- 起きたことを**説明しない**。状況の一行は、出来事の気配だけを短く書く（例:「蜂の通ったあとに、小さな種がこぼれた。」）。
- 祈り（願い）は時々、精霊の光として見える。直接「届きました」とは言わない。
- 7面目の確率（どの面も 1/7）と、願いの一致の「偶然なら」は、正直メーターとして明示を続ける。

## 6. ecology.v2 — 調和と菌根（2026-11-12 追加）

本人の決定（2026-11-12）:「陰陽・エレメント・5〜8芒星を仕組みとして」「菌根で島全体がつながって生きている」

### 6.1 調和（harmony.v1, Domain/Harmony.cs）

- 陰陽: 水・種（地）= 陰、光・風 = 陽。
- 窓: 今回を含む直近 **8** 投（八）。
- 調和 H（0〜8）= 窓に出た恵みの種類数（最大4）
  ＋ 陰陽の均衡（陰の数と陽の数の差が1以下）1
  ＋ 命（4種そろい、五つ目のエレメント）1
  ＋ 生き物の多様さ（その一投の自然シミュレーション後に庭にいる住人が5種以上）1
  ＋ 花の多さ（住人の一歩の後の花が7輪以上）1。上限 8。
  （harmony.v2 で「花の多さ」は「咲いている種の多様さ（4種以上）」に置き換えた。§7 参照）
- 芒星: H≥5 で五芒星（命）、H≥7 で七芒星（七つの灯）、H=8 で八芒星。海の七つの灯の輪の上に描く。
- 記録: `Resolved.ecology.harmony`・`star`・`yin`・`yang`。画面の表示は、最後に保存された記録の値を使う。

### 6.2 菌根（mycorrhiza）

- 網: マンハッタン距離 2 以内の植物どうしを結んだ連結成分（`Ecology.Networks`、セル番号順で決定的）。
- 分け合い: その一投で成長した植物を含む、3株以上の網だけが対象。
  その網の **まだ花でない最も若い 3 株** に、それぞれ成長 **+H×3**（0〜24）を足す。
  段階は既存のしきい値で進む（`Simulation.EmitStageEvents`）。偶然は使わない。水は動かさない。
- 記録: `Resolved.ecology.effects` の kind = `mycorrhiza`。

### 6.3 計測（720投・常に多い恵みを願い、七を取る方針）

- 調和の平均 4.96。芒星: なし 31%、五 59%、七 7%、八 3%。
- 菌根の成長: 1投あたり平均 38.7。虹の八: 約65投に1回（菌根で開花が早まったため。v1 は約80投に1回）。

### 6.4 見せ方（presentation、事実に束縛）

- 菌根の糸: `Ecology.Networks` の網の中を最小全域木で結び、地表すれすれに淡く描く（明るさは H に比例）。
- 一投後、その一投で成長した植物から網を伝って光が流れ、菌根で実際に分け与えられた株で灯る。
- 恵みの通り道: 水は泉から川を下って届け先へ、光は空から、風は島を渡って届け先へ（`RoundEvidence` の実際のセルへ）。
- 陰陽の偏りで日の色がわずかに変わる（陰→青み、陽→金色）。

### 7.2 土の条件（保存状態から毎回導く。新しい状態は持たない）

- 硬さ = 350 ＋ 高さ×400/1140 ＋（岩陰なら150）−（湿り600‰以上なら80）− 近く（距離1以内）のやわらげる植物の働き
  （葉以上で全量、芽で半量）。0〜1000。
- 水捌け = 300 ＋ 高さ×500/1140 ± 近くの水捌けを変える植物の働き（同じ重み）。0〜1000。
- 湿り = 土の水 / 容量（‰）。光 = 岩陰または減光のセルは日陰。

### 7.3 一投の流れへの追加（住人の後、菌根の前。決定的、偶然は保存済みの生態の bytes だけ）

1. **芽吹き（germinate）**: 種の決まっていない植物（サイコロの種・生き物の運んだ種・最初の庭の植物）は、
   その場所の条件に合う種のどれかになる。重み = 2 ＋ 親の種（蜂・蝶・綿毛が訪れた花）なら +10 ＋ 小鳥なら実のなる種 +6
   ＋ 綿毛なら風で種を飛ばす種 +8 ＋ 蝶なら蝶の好み×2 ＋ 蜂なら蜂の好み×2。最初の庭の植物は偶然を使わず id から決める。
   合う種がなければ先駆けのタンポポ。記録: effects kind=`germinate`（`species`、やわらいだ土でしか根づけなかった場合 `softened`）。
2. **合う場所で育つ（thrive）**: 条件に合う場所にいる植物（芽〜蕾）は成長 +4。
3. **訪れる者**: 蜂は蜂の好む花へ、蝶は蝶の好む花へだけ行く（避ける花には行かない）。蜂・蝶の運ぶ種は訪れた花の種を受け継ぎやすい。
4. **調和 v2**: 「花が7輪以上」を「咲いている種が4種以上」に置き換えた。

### 7.3a flora.v2 — 祈りの傾き（2026-11-13 追加）

- 芽吹きの重みに、直近 **8** 投の恵みの傾きを足す（その種に合う恵みが出た回数、0〜8）:
  水 → 湿りを好む種（湿り下限 400‰ 以上）、光 → 日向の種、風 → 風で種を飛ばす種と蜂・蝶に好かれる種（好みの合計 3 以上）、種 → 実のなる種。
- 場所の条件に合う種の中だけで傾く（合わない種は選ばれない）。親の種の継承（+10）はそのまま強い。
- 先駆けの遠慮: 合う種が4種以上ある場所では、先駆けのタンポポの基本の重みを 2 → 1 にする（荒れ地では先駆け、豊かな場所では譲る）。
- 混み合い: 距離2以内に同じ種が n 株あると、その種の重みを ×3/(3+n)（最小1）にする（同じ種ばかりにならない）。
- 日陰の種の土の硬さの上限: ホタルブクロ 500 → 650、ジギタリス 480 → 650。岩陰の土は +150 硬く、従来の上限ではほぼ根づけなかったため。
- 調査（360投、`SoilDiagnosisTests`）: 合う種がない芽吹きは 0%。タンポポは「どこでも合う」ため、平均4.3種の候補のうち同じ重みで
  選ばれ続けて最多になっていた（芽吹きの24%、サイコロの種の32%）。変更後はそれぞれ 15%・12%。
- 土の乾き: 植えられる55セルのうち35%が湿り100‰未満。1投あたり蒸発 約1179 に対し、入る水は サイコロ 約373＋天気 約633。
  水の量は自然シミュレーション（水収支の検証つき、§1 で不変）の決まりなので変えていない。乾いた庭には乾きに強い種が育ち、
  水の目が多い庭ほど湿り好きが増える（§8.4 の計測）。

### 8.3 見せ方と音（presentation、事実に束縛）

- 星（{5/2}・二つの三角の{6/2}・{7/3}・{8/3}）は**島の下の海**、七つの灯の輪（半径 13.4）の上に描く（2026-11-13 本人の指定）。
  以前ここに描いていた調和の芒星（§6.1）は表示せず、海の星は祈りの星だけにした（調和の値は画面の「調和 n/8」と音の層に残る）。
- 星はサイコロと**連動**する: 一投の間は、祭壇のサイコロがゆっくり回るのに歯車のように合わせて回り（サイコロの回転×0.35）、
  サイコロが転がる間は一緒に勢いよく回る。答えが出ると、サイコロから海の星へ光の糸が降り、そこで古い星が回りながら縮んで消え、
  新しい星が少し大きく現れて落ち着く。星の先から光の粒が昇る。八芒星は虹の八色。動きを抑える設定では回転しない。
- 七芒星では「ラッキーナンバー ７」と、前の目と今の目・偶然の確率を一行で示す。八芒星では「八芒星・八の虹」。
- 星の恵みを受けた株（記録された effects の kind=`star` のセル）に、光が降りる。
- 六芒星は陰（水色）と陽（金色）の二つの三角で描く。
- 星の頂点には水面に光の点があり、海の七つの灯籠は星が落ち着くと頂点の真上に寄る（動いている間は遅れてついていく）。
  五・六芒星では余った灯籠は小さくなって消え、八芒星では八つめの灯籠が加わる（2026-11-13 本人の指定「芒星の頂点に点が来るように」）。
- 七への灯: 直前の目 n（1〜6）のとき、**サイコロのまわり**を **7−n 個**の小さな灯が巡る（海の輪の上には頂点以外の点を置かない）（次にその目が出ればラッキーナンバー）。
  言葉では説明しない手がかりで、その目の確率は変わらない（偶然なら 1/6）。七の目の後は灯がない。
- 一投ごとの鐘は上のド（D5）。続く出目の音・星の和音と同じ D長調にそろえた（以前は C5）。
- 音（AudioSynth、D長調のドレミ）: 出た目 n の音（1=ド … 7=シ）を一音。星が落ち着くと和音
  （五=ド・ソ、六=ド・ミ・ソ、七=ド・ミ・ソ・シ、八=ドからドへ音階を昇り、ド・ソ・ド・ミの和音）。
  既存の鐘・開花より 5〜7 LU 小さく鳴らす（実測は PROGRESS.md）。

## 9. めぐり — 実って土に還る（lifecycle.v1、2026-11-13 追加）

本人の方向付け（2026-11-13）:「より仕組みとしてうまくいっている方で」。長く遊ぶと庭が止まる問題への対応。

### 9.1 調べたこと（`LongPlayTests`、6庭×200投、めぐりなし）

- 60投ほどで植えられる55セルが埋まり、植物は消えないため、その後は芽吹きが 0、サイコロの面から種の面が消える（80投以降 0/投）。
- 種の数は 12.5 のまま変わらず、200投で全株が花になり、成長も止まる。出目と祈りで庭が変わらなくなっていた。

### 9.2 決まり（Domain/Lifecycle.cs、偶然を使わない）

- 花は一投ごとに「咲いている投数」を1つ数える（`PlantState.BloomRolls`。0 のときは保存しないので、以前の状態のハッシュは変わらない）。
- 種ごとの寿命に達した花は、実りを残して**土に還り**、そのセルが空く: タンポポ 12、コスモス・ポピー・ヒマワリ・デイジー 20、ほか 30。
- 一投で土に還るのは**1株まで**（寿命をいちばん過ぎたもの、次にセル番号順）。庭が一度に寂しくならない。
- 土に還った株のとなり（距離1）の花でない株に成長 +40（kind=`humus`）。記録: effects kind=`return`（`species`）、出来事 `Returned`。
- 実行順: 生態の一歩の最後（星の恵みの後）。水は動かさない。
- 見せ方: 土に還った場所から淡い光の粒が昇る（PrayerStarSigil）。植物の表示は保存された状態に従って消える。

### 9.3 計測（6庭×200投、めぐりあり）

- 100投以降も 1投あたり 約0.6 の芽吹き、種の面が戻る（0.2〜0.4/投）、種の数 11〜13 を保つ。花は 13〜21 輪（以前は 200投で全55株が花で止まる）。
- 調和の平均 5.7（種の面が戻り、四つの恵みがそろいやすくなった）。そのため八芒星の調和の条件を 8 に上げた（§8.1）。
  星: 五 26.3%、六 53.2%、七 17.4%、八 3.2%。虹の八は約31投に1回（120投の計測）。

### 9.4 受粉と実り（lifecycle.v2、2026-11-13 追加）

本人の方向付け（2026-11-13）:「因果関係をより強化」。それまで蜂と蝶の訪れは、種をこぼす偶然のほかは次の代に関係していなかった。

- **受粉**: 花蜂・蝶が訪れた花は「受粉した」印を持つ（`PlantState.Pollinated`、true のときだけ保存）。
  蜂は蜂の好む花へ、蝶は蝶の好む花へ、しかも蝶は直近7投に水・風・光・種の恵みがそろったときだけ来る。つまり**出目のそろい方が、どの花が受粉するかを決める**。
- 同じくらい好まれる花は、投ごとに順番が回る（ワールドの改訂番号で並びが回る）。いつも同じ花ばかりが訪れられることはない。
- **実り**: 受粉した花が土に還るとき、**その場所に**種を残す（effects kind=`fruit`、seed）。種は親の種を受け継ぎやすく（+10）、
  直近の恵みに傾き（§7.3a）、近くの同じ種で薄まる（混み合い）。その場で芽吹く（germinate も記録）。
- **訪れのない花の跡**は空いたままになり、サイコロや生き物の運ぶ新しい種の場所になる。
- つながり: 出目 → 恵みと天気で育つ → 花 → 好む虫が訪れる（蝶は恵みのそろい方しだい）→ 受粉 → 実って同じ場所で次の代 → 庭の顔ぶれ。
  受粉しなかった跡 → サイコロの種の面が戻る → 祈りの傾きで新しい種。
- 見せ方: 一投ごとに一行で因果を出す（PrayerStarSigil）: 「星の恵み n株　水の恵み → 乾いた土の株へ」「蜂や蝶の訪れた花が土に還り、実りを落とした」
  「花がひとつ土に還り、となりを養った」。記録された effects だけから作る。

  （実りが場所を引き継ぐぶん種の面が減り、調和が下がったため。8 では八芒星 1.5%・虹 約65投に1回と少なすぎた）。
