# 土が記憶する庭 — ecology.v5

前回の24種・食物網・土の循環を引き継ぎ、庭の過去が次の芽吹きを支えるようにする。
花や生き物の種類の数を増やすことより、受粉・種・居場所の時間を深める改修。

## 保存と適用

- 新規の庭だけ `RunStarted.ecologyPolicyVersion = ecology.v5`。植物カタログは `flora.v2` の24種を継続。
- `ecosystem.succession` に土の種、花蜜と最終訪花の投数、生きている子株の由来を保存する。
- v3は `ecosystem` がなく、v4は `succession` がない。読み込み時にいずれも追加・再計算しない。
  v3の初期/24投、v4の初期/48投の既知ハッシュで旧規則を照合する。
- シミュレーション、水収支、面、意図の先行確定、保存済み乱数の64 bytesはそのまま。
  新しい乱数取得はなく、種の加齢・目覚め・花蜜・訪花経路は保存状態から決まる。

## 土の中に残る種

受粉と結実はv4のまま。散布は即座に株を作る代わりに、土へ1粒を残す。

- 空いていない土や、今はその種類に合わない土にも種は届く。永久に植えられない岩などには届かない。
  親の種の残量から同量を引き、親の種・個体ID・元の投・運び手・場所を保つ。別種には変わらない。
- 一投で土に届けられる種は、全経路と親株からの持ち越しを合わせて最大2粒。
  全体96粒・各セル3粒を上限とし、既存の種を押し出したり上書きしない。
- 親の寿命や衰弱による退場時は、残った実った種を1粒まで足元へ残す（同じ上限を使う）。
  次の開花の結実で古い種が残っている場合も同様に持ち越しを試み、残りは土へ還す。
- 運ばれたその投には芽吹かない。2歩以上たち、空き地・親種に合う土と光・養分2以上がそろうと目覚める。
- サクラソウ・スミレ・アネモネの種は「休息の頃」を経験し、次の「芽吹きの頃」を待つ。
  その経験も保存し、再読み込みで失わない。これは現実の温度や日付ではなく、投数で巡る庭の時期の規則。
- 寿命は通常96歩。ポピーとコスモス64、ヒマワリ80、アキノキリンソウ128、シロツメクサ144、休眠する3種160。
  待ち切った種は落ち葉1へ還る（落ち葉100の上限内）。分解者による養分の循環へつながる。
- 目覚めは一投2株まで。古い種を先にし、同じ年齢は場所の順を投数で巡らせる。同一セルに2株は作らない。
  退場した株の場所は次の投から使う。芽吹く株は成長250・Sproutから始まり、養分を2消費する。
- 個体の由来には死んだ親のIDも残す。現在の株の一覧から親がなくなっていても、子はその種を引き継ぐ。
  死んだ個体自身の花蜜や現在の個体用メモリは片付け、過去の記録は追記ジャーナルに残す。

## 花蜜と訪花

v4では候補セルの最初の3つばかりが訪問されるため、後ろの花に受粉が届かない偏りがあった。

- 開花して元気で、居場所の条件が合う花に蜜を補う。晴れで2、薄曇りで1、小雨で0、上限6。
- 蜂・蝶・ハナアブは実際の訪花ごとに蜜を1消費する。蜜がなければ受粉も追加しない。
- 好みの花で、蜜があり、受粉をまだ待つ花を先にする。その中では長く訪れていない花、好みの強い花を優先。
  最後の同順位も投数によって巡り、毎回同じセルに固定しない。
- 蜂の後に蝶が訪れる時は、その時点の残った蜜から経路を選び直す。蜜の少ない薄曇りでも、
  蜂が食べ終えた花に張り付かず、別の好みの花を訪れられる。
- ハナアブの訪花は開いた形の花（デイジー・ノコギリソウ・アキノキリンソウ・キンポウゲ）に限る。
- 分解者は分解できる落ち葉の多い土、捕食者は獲物の多い場所を優先し、同順位は投数で巡る。
  存在する残りの資源だけを消費する原則はv4から維持。

## 庭を観察

常時の画面は静かなまま、右メニューに「庭を観察」を追加する。

- 全体／水辺／岩陰／草木の陰／乾いた草地／花の草地を切り替える。
- 居場所の区画数、株と花の数、落ち葉と養分、根づいている植物を現在の状態から表示。
- 土に残る種は、未成熟・空き地・休息の頃・芽吹きの頃・居場所・養分のうち、今待っている理由を示す。
- 株は由来、花蜜、乾きすぎ・水の多さ・土の硬さ・排水・日向と陰・養分不足・小虫・混雑を読み取れる。
  負担が高いまま条件が戻った株では、回復に時間を要する状態も区別する。
- 生態イベントを推測して表示しない。観察は現在の条件、履歴の文章は保存された原因から作る。
- 種の着地はその投の運搬演出、後の芽吹きは地面からの光と音で区別する。
  記録の「土に残った種」と「眠った種が芽吹いた」も別に数える。

## 検証

`dotnet test tools/ecology-check/Ecology.Check.csproj --configuration Release` で、実際のC#を実行する。
休眠、土の条件の変化、親の退場後の子、有限の蜜、広い草地への訪花、蜂の後の蝶の経路、
資源と個体数の上限、観察の根拠、深いコピー、JSON保存、v3/v4の既知ハッシュ、384投の継続/復帰の一致を検証する。

Unityエディタでの型解決、描画、UI入力、音と性能の確認はこの検証とは別で、リリース前に必要。
