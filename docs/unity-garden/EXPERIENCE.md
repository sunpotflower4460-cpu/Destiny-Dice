# 一投の体験・画面・展示の進め方

設計版0.6 / `designCandidate` / 2026-11-11。**Unityの画面・操作・実機での見やすさは未検証。**

一つの庭と今の空を見て、意図を添えても添えなくても振り、起きた変化を見つける。届け先はおまかせでも、気になる場所を選んでもよい。天候、実際の入力先、前からの庭が重なり、遊ぶ人の選択と偶然から違う育ち方が残ることを目標にする。

本書は画面と操作の設計であり、抽選・保存の状態機械を追加するものではない。届け先と多様性は[DIVERSITY.md](./DIVERSITY.md)、配面・文章は[GAMEPLAY.md](./GAMEPLAY.md)、天候の規則は[WEATHER.md](./WEATHER.md)、自然の計算は[SIMULATION.md](./SIMULATION.md)、確定と回復は[DATA_CONTRACT.md](./DATA_CONTRACT.md)、実装範囲は[ROADMAP.md](./ROADMAP.md)を正とする。

## 1. 最初の数投で伝えること

初回の入口は、庭とサイコロを同じ画面に置く。名前の登録、長い説明、目標設定、カードを開く操作を開始条件にしない。最初の案内は「触れて、離すと振れます。意図は、添えても添えなくても。」の一つに留める。

| 場面 | 庭で見つけられること | 画面の役割 |
|---|---|---|
| 最初の準備 | 晴れた庭に、芽・つぼみ・空き土、岩、湿りの違いがある | 今の天候、おまかせで決まった届け先、六つの面、「振る」を同時に見せる |
| 最初の解決 | 選ばれた入力が、どこへ入ったか | 該当面→作用場所→実際の変化の順で視線をつなぐ |
| 続く数投 | 同じ入力でも、前から残る水や成長量が結果に関わる | 直前のことばを残し、次の6面を区別して表示 |
| 天候が変わる期 | 薄曇りや小雨の中では、同じ面の入力が違う条件へ重なる | 次の一投の天候と、その条件で作った6面を同時に公開 |
| 段階が進んだとき | 葉やつぼみなど、庭に残る変化が増える | 実イベントに対応する光とアクセントを一度だけ使う |
| 花が残る庭 | 水・風・光の違いを眺め続けられる | 新しい庭は任意操作。花を消して継続を促さない |

これは説明する順序であり、出目を水→風→光へ固定する進行ではない。最初にどの入力が出ても、その入力の実適用を見せる。段階成長が起きない一投にも、水の移動、吸水、風の遮蔽、照射、種の配置などの観察対象を持たせる。

初回の届け先設定は「おまかせ」。任意に開く選択欄には「おまかせ／入口／岩陰／ひらけた土」を置き、一度選んだ設定を同runで維持する。場所を選ばず振り続ける遊びも成立させる。おまかせは同じ場所を続けて選ぶ場合もあり、空き土や見栄えを理由に引き直さない。

発芽などの発見は保存済みイベントから導く。通知を閉じる、報酬を受け取る、発見一覧を埋める操作は付けない。新しい段階を示す短い表示は通常の主焦点に含め、別の祝福音を重ねない。

初めの三つの正常解決投は固定の晴れ。その後は三つの正常解決投ごとに次の天候を選び、同じ天候が続くこともある。天候が変わるたびに案内を閉じたり、操作を確認したりする必要はない。庭の時間は一投ごとに進み、待つ長さや祈る長さで雨量・成長・次の天候を変えない。

### 1.1 育った庭と、今回の場所へ届く種

種を置ける場所は、今回のPreparedに固定された届け先を中心とする各recipeの範囲内の空き土である。入口・岩陰・ひらけた土では範囲が異なり、同じ場所へ重ねるか、次の投擲から別の場所へ移すかで、植物の配置とその後の条件が変わる。現在の範囲と全地点の上限は[DIVERSITY.md](./DIVERSITY.md)、基礎地形とv0.5までの固定anchorの参照結果は[GARDEN_LAYOUT.md](./GARDEN_LAYOUT.md)に分ける。旧固定anchorの21個体上限を、新しい三地点の合計上限として表示しない。

種の面の任意説明では、そのrecipeが届く範囲と空き土を薄い輪郭で示す。種が6面にないときも、意図欄の種の説明から同じ範囲を見られる。説明を開くだけで目標を変更せず、閉じたら同じPreparedへ戻る。主画面に新しい常設カウンターや確認画面は置かない。

| 開始時の状態 | 任意説明の短い例 |
|---|---|
| 種recipeは候補になるが、今回の6面には選ばれなかった | 「今回は、種の面はありません。」 |
| ひと粒の種の範囲に空き土が0 | 「ひと粒の種が届く範囲は、いま埋まっています。」 |
| 種の舞いの範囲に空き土が0 | 「種の舞いが届く範囲は、いま埋まっています。」 |
| 種の舞いの範囲に空き土が1 | 「種の舞いには、二つの空き土が必要です。いまは一つ空いています。」 |

説明は公開中Preparedの届け先・開始snapshotと固定map/profileから導く投影であり、別の進行台帳を作らない。次からの場所を選んでいても、今回の範囲説明はその選択へ切り替えない。両recipeが候補外でも、外側に1セル残っている場合を「空き土がない」としない。今回の範囲外に空き土があればそのまま見せ、種を置くための自動移動や範囲拡張はしない。これは現在の候補条件の説明であり、次の出目や育成の正解を案内するものではない。

花の段階まで育った個体は、その形と履歴を保つ。成長量が増えない一投でも、その回に起きた土への吸水、水面の変化、風の通り方、光の届く場所を見せる。整数成長0だけから、乾燥・過湿・失敗という理由を作らない。個体の詳細では保存された段階と同じ場所の状態を読めるようにする。

全個体が花になった境界状態でも、庭と天候の更新、適合する文章、記録、次の投擲を継続できる。「完成」で操作を閉じず、新しい庭は§8の任意操作に留める。花を消す、成長音を繰り返す、一定時間で自動リセットする経路は加えない。

## 2. 一つの画面の構成

展示の基準は横画面。PCとスマホで、庭・6面・主操作・ことばの関係を共通にする。正確な寸法はG3の端末で確定する。

| 領域 | 常に分かること | 初期の配置候補 |
|---|---|---|
| 庭 | 入力先、植物、岩、水の現在の見た目 | 左側の広い領域。固定カメラ |
| 天候の帯 | 今の空と、その一投で庭全体に働く条件 | 庭の上にアイコンと「晴れ／薄曇り／小雨」の短い一行 |
| 届け先の要約 | 今回の作用点と、変更した場合の次からの設定 | 庭の端に「今回：入口」。同じ欄から選択を任意に開く |
| 6面一覧 | 番号、系統のアイコン、入力名 | 右側、3列×2行 |
| 意図の要約 | 目標と選んだ方法。未設定も分かる | 一覧の上、一行または二行の小さな帯 |
| 主操作 | 今振れるか、処理中か | 一覧の下。サイコロと「振る」 |
| ことば | どの一投についての文か | 庭の下に固定した最大2行の領域 |
| 補助操作 | 記録、音・表示設定 | 画面上端。主操作から離す |

ことばの出現で庭や6面の位置をずらさない。文字のないときも領域を確保する。主焦点を示すためにカメラを毎回自動回転・急拡大せず、同じ構図の中で場所を追えるようにする。

### 天候と、サイコロから来る入力を見分ける

天候の帯はPrepared.weatherContextを表示する。届け先・6面と同じ公開境界を使い、天候や届け先だけを先に見せて後から配面を変えたり、表示後に別の天候・場所へ差し替えたりしない。最初の晴れが固定であることと、庭の時間が一投ごとに進むことは任意の説明で読めるようにする。

| 表示例 | 作用する範囲 | 見分け方 |
|---|---|---|
| 「今の空：小雨」 | 天候として庭全体の非solidセルへ降る | 空・薄い雨粒・天候の帯で広がりを示す |
| 「面4：小さな雨」 | サイコロの水入力として今回の届け先の周囲へ降る | 選ばれた面と実作用範囲の輪郭を対応させる |
| 小雨の中で「ひと筋の光」 | 雨の条件に、サイコロの局所光が加わる | 空を晴れへ置換せず、その場所に届いた追加光を見せる |

天候アイコンと、サイコロの系統アイコンは別の欄に置く。天候の雨を「水の面が出た」と表示せず、ダイスの風で天候そのものが変わったような切替もしない。説明を開いたときだけ、天候の範囲と面の作用範囲を見比べられる。

準備・意図・履歴の間も空や雨粒の装飾は動かせるが、土の湿り、水面の高さ、植物の段階は確定状態のまま。待機中の雨粒が新しい水たまりを作る演出はしない。前回の過程再生中はその回の天候と届け先を使い、終状態を見せた後に次のPreparedの天候・届け先・6面へ切り替える。

### 今回の届け先と、次からの選択

三地点は「入口」（cell85）、「岩陰」（cell135）、「ひらけた土」（cell154）。その地点が水・風・光・種の中心となり、入力ごとの量・半径・時間は既存recipeに従う。「おまかせ」は保存済みの配面用材料から今回の地点を選ぶ設定で、選んだ場所へ実際の自然入力が入る。プレイヤーの性格や願いの意味から場所を推定する機能ではない。

| 場面 | 要約の例と操作の意味 |
|---|---|
| おまかせで入口が公開された | 「今回：入口（おまかせ）」。そのまま振れる |
| 公開後に岩陰を選んだ | 「今回：入口」「次から：岩陰」。公開中の配面と作用先は保持する |
| 岩陰を使う次のPreparedが公開された | 「今回：岩陰」。固定設定は変更するまで続く |
| おまかせへ戻した | 「次から：おまかせ」。次も同じ場所になる可能性がある |

場所を変えられるのは「振れる」「変化を提示中」の状態だけとする。選択の受理後、確認ボタンや読了を求めない。今回の結果を再生中なら、今回の場所と出来事を見せたまま、次からの設定だけを示す。保存・準備中は選択を受け付けず、押し続けた操作を準備後へ予約しない。表示を閉じるreleaseから投擲や追加選択を起こさない。

次のPreparationStartedより先にwriterが受理・保存した最新の選択を、その準備で使う。表示中のPreparedへ後付けせず、次の準備が始まった後の入力を遅れて反映しない。確定境界と復元元はDATA_CONTRACTに従う。「次から」の表示は保存成功した設定に対応させ、保存中を選択完了として見せない。保存障害時は同じ回復案内へまとめる。

場所を選ぶ操作は、面番号・系統への意図、祈る方法、本文を変更しない。植物の詳細や面の説明を見る操作も場所選択にはしない。場所の固定とおまかせのどちらにも追加の達成報酬・成長補正を付けず、庭の条件と履歴から違いが生じるようにする。

### 状態から見た目への対応

土・水・葉・光・植物は、同じ場所のモデル値をそれぞれ参照する。見た目の明るさや揺れを、別の自然量の代理にしない。

| 見せるもの | 参照する量 | 表現の境界 |
|---|---|---|
| 土の湿り | `soilCapacity > 0`のセルの`floor(1000 × soilWater / soilCapacity)` | 土中水の絶対量で色を決めない。容量0は土の湿り描画の対象外 |
| 地表の水面 | 同じセルの`surfaceWater`と地形高 | 土中水を水面へ足さない。雨粒の個数から水量を推測しない |
| 葉の揺れ | 再生中の同じtick・セルの合成実効風 | 岩陰の減衰を反映。水や種を風で運ぶ表現は追加しない |
| サイコロの局所照射 | 再生中の同じtick・セルの追加実効光 | 天候の基礎光と分け、追加分が0の場所を照射したように強調しない |
| 植物の段階 | 表示対象snapshotの保存段階。再生中は同じ計算traceの段階 | 段階越えを表示し、同じ花をもう一度開花させない |
| 種から育つ花の色・幅（任意表現） | 実際のSeedPlacedの出生条件と、runに固定した見た目profile | 一つの植物modelの見た目として維持。現在の雨や土で毎回変えない |

例えば土中水200でも、容量200なら水分比1,000、容量1,000なら水分比200として描く。材質の色や反射はこの比率を入力とする候補であり、実機で読み取りやすさを確かめる。両方を同じ湿りに見せてよい根拠にはしない。

合成風・追加光は、その40tickの再生中の場である。次のPreparedを公開した待機画面では、そのセルの遮蔽を適用した天候だけの実効場を使い、前回ダイスの局所風・追加光を持ち越さない。静かな余韻は記録を変えない装飾として終える。`meanLight`を新しい局所光へ読み替えない。

面の説明で出す輪郭は、公開中Preparedの届け先と保存済みrecipeの直接作用範囲を示す。まだ抽選していない水流・成長・開花のアニメーションを始めず、予測した成功場面を見せない。

出生時の見た目を採用する場合は、SeedPlacedの`soilQAtPlacement`が400未満／400〜700／700超のどれかに対応する三つの配色と、その回の晴れ／薄曇り／小雨に対応する三つの花弁幅を組み合わせる。具体値はDIVERSITYの見た目profileを使い、同じ個体で発芽から成熟まで同じ出自を参照する。初期配置の植物は中立の見た目を使う。出生記録が確認できない個体について、現在の土や空から過去の条件を作らず、確認できる段階を示して根拠のない由来説明を付けない。

これは植物種や成長能力を増やす機能ではない。三つの色と三つの幅が、祈りの強さ・運・優劣を表す説明はしない。既存の28文へ出生条件を根拠なく混ぜず、同じ一つの植物modelと共通の成長段階で表現する。展示では、届け先に応じた実際の変化と復元を先に完成させ、色・幅の表現はその後に採用する。

### 小さい横画面の候補基準

- 6面は横スクロールや裏面めくりへ隠さない。番号・系統アイコン・入力名を同時に出す。
- 操作領域は48 logical UI units以上、ラベルは16以上を初期目安とする。これは本作の候補値であり、OSの適合判定や実測済み寸法ではない。
- 一覧の入力名は最大2行で折り返す。「通り抜ける風」などを省略記号で同じ名前に見せない。
- 右側操作領域の幅は280～340を候補とし、余った幅を庭へ使う。safe area内へ収める。
- 空間が足りない場合は余白・装飾・カード紋章を先に縮める。6面や主要ラベルが欠ける端末は、その配置で合格にしない。
- 色に加え、面番号・アイコン・名称を使う。消音や低刺激設定でも、選ばれた面と作用点を理解できるようにする。

logical UI unitsはCanvas上のレイアウト用単位。実際の文字の大きさ・指の届きやすさ・植物の見分けやすさは表示倍率と端末で確認する。縦持ち、極端に細いPCウィンドウ、文字拡大の追加配置はG4で個別に確認し、未確認の画面比へ対応済みとしない。

## 3. 画面状態と、操作を受け付ける境界

以下はUIの表示状態であり、新しいjournal recordではない。保存されている段階と、今見せている庭を区別する。

| UI状態 | 表示 | 受け付ける操作 |
|---|---|---|
| 復元中 | 「庭の記録を開いています」 | 音・表示設定。投擲は受け付けない |
| 配面準備中 | 庭の確定終状態。「次の一投を用意しています」 | 音・表示設定。届け先変更・投擲の予約はしない |
| 振れる | 保存済みPreparedの天候・届け先・6面、意図の要約 | 投擲、意図の編集、次からの届け先選択、面の説明、記録 |
| 触れている | ダイスの縁が静かに光る。6面は固定 | 同じ入力のrelease、取り消す操作 |
| 確定・解決中 | 控えめな待機反応。時間がかかる場合に「一投を記録しています」 | 追加投擲・意図編集・届け先変更を受け付けない |
| 変化を提示中 | 確定出目、同じモデルから得た過程、今回の届け先、主焦点 | 「演出を省略」、次からの届け先選択。新しい投擲は受け付けない |
| 記録を閲覧中 | 選んだ回と当時の庭を明示 | 記録内の選択、「今の庭へ」。投擲しない |
| 回復待ち | 保存状態に対応した短い案内 | 同じ処理の回復操作。新しい抽選を始めない |

`Resolved`の保存成功時点でCoreは終状態を持つ。一方、その過程を再生している画面は途中の見た目を示すことがある。**次の天候・届け先・6面の公開・意図編集・Roll受付は、表示している庭がPreparedの`beforeRevision / beforeStateHash`に対応する終状態になってから**許可する。

v0.6では、過程再生の終了または省略→確定終状態の表示→それまでに受理した届け先設定をwriter順で保存→PreparationStarted→必要な期の天候確定→今回の地点と配面を準備→一緒に公開、の順にする。提示中の場所選択を受け取れるよう、次のPreparationStartedや配面生成を内部で先行させない。保存成功前に未来の天候・場所・配面・結果を見せない。

提示の終了や省略は、結果の読了を意味しない。PresentationReceiptの欠落も読了確認の理由にしない。ただし保存adapter自体が失敗している間は、新しい抽選を開始しない。

### 入力を次の一投へ持ち越さない

一つの操作は、開始したrun・Prepared・UI入力世代に結び付ける。画面の開閉・提示の終了・新しいPreparedの公開時は、新しいpressを必要とする。

| 操作 | 扱い |
|---|---|
| ダイスを押して、そのまま離す | 最短時間なし。同じPreparedに対する投擲要求を1件出す |
| 「振る」を一回タップ | 同じ投擲要求へ進む。短い操作も有効 |
| 連打・二本指 | 最初に受理した1件だけ。残りを次のroundへ予約しない |
| 押したままダイス領域の外へ出す | そのgestureを解除。戻って離しても振らず、新しいpressから始める |
| フォーカス喪失・pointer cancel・バックグラウンド移行 | 触れている表示と音を終了。取得前なら自動で投擲しない |
| Enter / Space | 主操作にフォーカスがあるときだけ1件。キーの自動リピートを投擲へ変換しない |
| 「演出を省略」や画面を閉じるrelease | その操作で消費。直下のダイスや次のPreparedへ流さない |

主操作の二つの表現が同じpointerから二重発火しないよう、Applicationへ渡すcommandIdを一つにする。受付可否はUIボタンの見た目だけで判断せず、現在のrun/round/状態とも照合する。

## 4. 意図を添える操作

「意図を添える」から、小さな設定欄を任意に開く。欄を閉じる操作は編集の終了であり、投擲ではない。毎投の保存ボタンを置かず、今回の意図はRoll要求を受けたときにIntentCommittedへ確定する。

### 4.1 目標と方法は別にする

| 項目 | UI例 | 記録上の意味 |
|---|---|---|
| 系統の目標 | 「水を願う」 | 次の配面でもwaterを維持し、その回の該当面を求め直す |
| 面番号の目標 | 「3を願う・今回は風」 | faceId=3を維持。面の中身が変わっても、目標を風へ変換しない |
| 目標なし | 「目標：指定なし」 | 面の一致率に分類しない |
| 方法 | 「指定なし／自然に任せる／心で思う／祈る／声にする」 | 選択したラベル。順にunknown/asIs/intention/prayer/spoken |
| 任意の短文 | 「言葉を残す（手入力・任意）」 | 入力された本文。後から的中条件を作らない |

構造化した目標がある場合はface/element、目標がなく本文だけある場合はfreeText、どちらもない場合はnoneに対応させる。方法を「祈る」にしただけで比較目標を作らない。

6面一覧をタップしたときは説明と作用範囲を見る。目標の変更は意図欄で行う。作用点を見た操作が、そのまま予測対象の変更になることを避ける。

### 4.2 継続する選択を見えるようにする

同runでは前回確定した目標・方法・本文を次回の初期値にする。要約には「目標：水」「方法：祈る」のように現在の選択を出す。意図欄には「この選択は、次の一投にも使います」を一度に読める場所へ置く。

系統が次の6面にない場合もその目標を保ち、「水の面：0/6」と示す。選び直しを必須にせず、目標を別系統へ置換しない。面番号目標では「3：そよ風」のように現在の中身を必ず添える。
天候が小雨になっても「水を願う」を自動達成にせず、あくまで今回の水の面と出目で比較する。天候を見て次の目標を変えることは意図確定前まで可能とし、その変更を記録する。意図が確定した後に天候や6面を変えない。

欄を閉じる、記録を見る、同じprocessで短く中断するだけでは編集中のdraftを消さない。process終了後の確実な復元元は、保存済みIntentCommittedとPreparedである。未確定draftを別途保存する場合もUI設定として区別し、確定済みの意図を書き換えない。未保存の本文を復元できたように表示しない。

G3のUIでは押している間の編集欄を開かず、Roll受付時に表示中の選択を一つのsnapshotとして捕える。保存仕様が許す未確定draftの変更とは区別する。確定処理の最中に戻る操作があった場合は、DATA_CONTRACTのコマンド順序で取得前取消か取得後の表示終了かを決める。

### 4.3 声と祈りについての短い案内

「声にする」を選ぶ欄では、次の一文を常に読めるようにする。

> 声そのものは保存せず、選んだ方法を記録します。残したい言葉は入力できます。

マイクの録音中に見える赤点・波形・字幕を出さない。「祈りを受信」「声を認識」「集中が十分」といった自動判定も出さない。長押し時間は実際の操作時間として保存し、祈った時間や発声時間とは表示しない。

## 5. 入力・変化・余韻を同じ場所で見せる

PresentationPlanに保存された主焦点・補助・根拠を使う。画面の都合で別の目立つ植物へ差し替えない。

| 段階 | 見せるもの | 候補の長さ |
|---|---|---|
| 触れる | 縁の光と、わずかに静かになる環境音 | 押している間。最低時間なし |
| 転がる | 一つのダイス。確定出目に収束する | 初期候補0.8秒。保存待ちは結果を伏せた待機へ分ける |
| 入力が届く | 該当面と実作用先を対応させる | 自然変化の再生冒頭 |
| 庭が変わる | 保存結果と同じ天候＋ダイス入力による計算経過。水・場・成長を補間 | 40tickを初期候補4秒で再生 |
| ことばと余韻 | 終状態、主焦点の短文、小さなカード名 | 次を振るまで本文を読める |

これらは提示速度の候補であり、40tickの計算量は変えない。ダイスの最終面の着地・表示はResolvedの保存成功後に行う。端末が遅くてもCoreのtickを捨てない。traceが復元できない場合は確定終状態と保存文を見せ、見栄えのために別の変化を生成しない。

「演出を省略」はResolved後にだけ有効。過程の再生を終え、同じpostStateへ表示を合わせる。省略しても段階成長・カード・文章・観察値は変わらず、次回には新しい操作を必要とする。

### 5.1 光と音の量

主焦点は一つ、補助は最大一つ。水なら青緑の小さな反射、風なら淡い流線と同じ風量場による葉の揺れ、光なら淡い金色の照射、種なら実配置点の小さな明滅を候補にする。色だけに意味を任せない。

鐘は一度、自然音loopは最大一系統、段階成長のアクセントは最大一回。入力音や成長音を再生したまま次の一投へ重ねず、環境音へ穏やかに戻す。花が複数開いたときも全個体の状態を描き、強い音を個体数だけ鳴らさない。
天候の環境音もこの自然音loop上限に含める。小雨のloopとダイスの風loopを別枠で増やさず、静かな空間の中で主焦点を聞き取れるようにする。天候が変わっただけで追加の鐘を鳴らさない。

低刺激設定では強いBloom・流線・点滅・カメラの動きを抑え、面の枠、作用範囲の輪郭、植物の段階、本文で同じ情報を示す。音量0でも一投の完了を判断できるようにする。

### 5.2 前回のことばと、次の6面を混ぜない

提示中はその回の6面に選択結果を示す。次のPreparedを公開するときに一覧の見出しを「次の6面」へ切り替え、残す本文には「前の一投」または「3投目のことば」の識別を付ける。カード名も本文と同じroundへ属する。

新しい投擲要求を受理したら、前回本文の強調を解き、結果待ちへ移る。過去文は履歴に残る。文章が完全に同じでも、別roundとして記録されたことは履歴から確認できる。

カード名・紋章はcardStatus=drawnの回だけ本文の脇へ小さく置く。カードの説明は任意に開く。「根：土や根元に残る変化へ目を向ける」など、見る角度を短く示す。カードを開かなくても次の一投へ進める。

### 5.3 省略・中断・遅れた描画で音を持ち越さない

一投の再生は、Presentation内の`ownerToken`と一方向へ進む`cursor`で管理する。tokenは現在のrun・Resolved・提示attempt・表示世代に結び付ける。音やFXのcallbackは同じtokenが有効な場合だけ受理し、発火済みcueを同じ再生内で再発火させない。これらは破棄できる表示用メモリーであり、新しいjournal recordや庭の状態にしない。

cueは保存済みPresentationPlanとその根拠から作り、モデルtickの昇順で扱う。同tickの注目cueは主焦点、補助の順とし、同じ役割内は固定cue ID順にする。出目の鐘は庭の過程再生を始める前の一回に留める。自然音loopの強さや葉の揺れはその時点の場へ追従し、雨pulseやセルイベントごとに音を追加しない。
主焦点の段階cueは採用文のpredicateBindingsと元eventで個体・tickを定め、補助の段階cueも選択済み根拠eventを使う。group.firstTickを、選ばれた個体の発芽・開花tickの代理にしない。

一つの描画更新で強調cueを複数発火させない。低fpsで複数のcue時刻を越える場合は、表示cursorを次のcue境界で止めて順に進め、必要なら候補4秒より再生を長くする。Coreの40tickや出来事を削らず、音だけを一斉に追いつき再生することもない。
同tickのcueが残る間はcursorをそのtickに保ち、未発火分を次frameへ順送りして処理済みcueだけを除き、`prevTick < cueTick`だけで残りを落とさない。

| 表示上の出来事 | 残すものと、終了するもの |
|---|---|
| 演出を省略 | tokenを無効化し、未発火cueを破棄。局所の音・強調を終了し、同じpostStateと保存文を表示 |
| Resolved保存後の提示中にフォーカス喪失・アプリ中断 | 再生を終了してtokenを無効化。復帰時は同じ保存終状態と文へ静かに収束し、過去の鐘・成長音を自動再生しない |
| 次のPreparedの公開・run切替 | 前のtokenを無効化してから公開。遅れて届く前回の音・光・焦点変更を受理しない |
| traceを失った復帰 | 確認できた保存終状態と文を表示。失った過程や未発火音を補わない |

省略・中断によるcueの破棄は、保存済みイベントや文章を消すことではない。新しい自然音loopへ戻す場合も§5.1の最大1本を守り、前回の入力音を次の空へ重ねない。Presentationの終了は、未完了の保存・取得・解決を取り消す操作にはしない。

PresentationReceiptは引き続き提示処理の報告とし、音を聞いた・文を読んだことを表さない。復帰後や省略後に追加の確認を求めず、終状態とPreparedの対応が取れてから、新しい操作で次を振れるようにする。

## 6. 振り返りは一つの入口から

「記録」は投擲を受け付けられる状態で開く。開いている間は新しい投擲を始めず、庭のCoreを経過時間で進めない。閉じたら同じPrepared・目標・庭に戻る。

| 見方 | 最小の表示 | 表示上の条件 |
|---|---|---|
| 庭の歩み | round順の天候帯・今回の届け先・ダイス入力記号、水量・成長の推移、段階イベント | 水量と成長量は別の縦軸・別の小グラフ。異なる単位を同じ量として重ねない |
| 意図と出目 | 実際の一致と、配面に対応する基準の二つの線 | 同じ比較対象集合。対象数・該当面なし・結果不明を併記 |
| 一投のつながり | 天候と、確定した届け先へのダイス入力から、局所状態→適用規則→出来事へつなぐ | 同じ対象・区間の保存根拠がある関係だけを結ぶ |

最初に開く範囲は現在のrun。初期版は全画面で複雑なfilterを並べず、見方の切替と一投の選択から始める。選んだ回の天候・届け先・おまかせ／固定の設定・方法・意図・面・カード・本文は詳細で読める。

意図と出目の比較対象は、事前に確定したface/element目標があり、出目が既知で、0 < p_t < 1の回。実際の累積一致数と、その同じ回のp_tの累積を示す。p_t=0、p_t=1、結果不明、比較対象外の目標は件数を分ける。少ない記録に有意差や祈りの効果を示すラベルを付けない。

解決できなかった回を0の水量や成長量で補完しない。グラフには記録が途切れたことを示し、結果不明と、出目は既知だが庭の解決が途中の状態を区別する。意図の一致はDATA_CONTRACTの既知結果から集計し、庭のグラフの点がない理由で除外しない。
天候が準備済みでも庭の解決がない回には、40tickの雨や成長を描き足さない。「天候は既知・庭の変化は未解決」と区別する。過去の天候はその回の記録から表示し、現在の空へ置き換えない。

一投の詳細で過去の庭を見せる場合は「この一投の庭」と表示し、そのsnapshotを閲覧用に使う。「今の庭へ」で現在の確定状態とPreparedへ戻る。履歴閲覧を再適用・再抽選・過去runの再開にしない。

「なぜ？」を開く場合も、まず「風→蒸発→土の湿り→成長」のような短い関係を見せ、必要なときだけ数値・対象・ruleIdの詳細を展開する。根拠のない列や矢印を埋めるための説明は生成しない。
届け先の選択は、実入力が入る中心を決めた操作として表示する。入力が届いていない個体へ「この場所を選んだから咲いた」という矢印を引かない。植物の個別履歴を開けば、実際の播種位置と、そのときの記録済みの空・土の状態を見られる。出生時の見た目を使う場合も、この同じ記録を根拠にする。

入力先から離れた植物の変化も、同じ40tickに起こり得る。「前からの庭の状態」「この一投の天候」「サイコロからの追加作用」を別の入口として見せ、同じ対象に実際に届いた関係をつなぐ。雨とダイスの水が混ざった後の土中水を、根拠なくどちらか一方の水と呼ばない。

JSON／CSVの書き出しは記録画面の明示操作。表示中のrunと範囲を示し、OSの保存・共有先選択へ渡す。手入力した本文も含むことをその操作の近くに表示する。自動投稿・自動送信はしない。

## 7. 中断と保存障害の見え方

技術上の段階をすべて画面へ並べず、ユーザーが次にできることを短く示す。案内は事実が確定してから表示する。

| 保存上の状態 | 案内例 | 次へ進む条件 |
|---|---|---|
| 同じPreparedへ復帰 | 「同じ空・場所・6面から続けられます」 | 表示と復元revisionを揃え、新しいpressを受け付ける |
| 天候材料は保存済み、配面準備が中断 | 「次の一投を用意しています」 | 同じ天候期の材料を使って準備。空を引き直さない |
| 出目または材料が保存済み | 「保存した一投を開いています」 | 同じ材料から回復・解決。新しく振らない |
| 中断した出目が回収不能で、未成立記録の保存に成功 | 「中断した一投は、結果不明として記録しました」 | 庭は元の確定状態。次のroundを準備できる |
| カードだけ未成立、庭は解決済み | 「カードは取得できませんでした」 | 入力の事実文を表示。出目・庭は保つ |
| 保存adapterが失敗 | 「記録を保存できません。確認して再開してください」 | 同じ処理の保存・回復が成功するまで新規取得しない |
| 内容の検証に失敗 | 「記録を確認できません。新しい投擲を止めています」 | 原本を保全し、DATA_CONTRACTの回復経路へ |

「保存しました」は保存成功後だけに使う。保存失敗の操作名は「再開する」とし、「振り直す」へ置き換えない。すでに保存した結果や材料がある場合は、それを回復する。

結果不明の記録に成功した回は、読了確認なしで次を準備できる。通知を確認するまで抽選が自動で始まる設計にはせず、次の抽選には必ず新しい操作を必要とする。

## 8. 新しい庭と、次の来場者

新しい庭は設定欄から「新しい庭を始める」を明示的に選ぶ。近くに「今の庭は記録に残ります」と示す。設定を開く→開始操作の二段階とし、毎投の確認にはしない。

前のroundを取得前取消または取得後の確定・未成立へ決着させ、RunClosedを保存してから新しいRunStartedへ進む。元の記録を削除せず、同じrunIdを使い回さない。無操作時間や長い祈り時間を理由に、自動で新しい庭へ切り替えない。

| 引き継ぐもの | 新しいrunで初期化するもの |
|---|---|
| 端末の音量、低刺激設定など表示の好み | 目標、方法、自由文、届け先設定と次からの選択、操作時間の計測 |
| 保存済みの旧run | 新runの庭、天候期、配面、カード、文章、発見の表示 |

展示の来場者交代には同じ経路を使う。前の来場者の本文は、切替を開始した時点で通常画面から外す。来場者向けの記録閲覧・書き出しは現在runに限定し、過去runの一覧や本文を同じ画面へ戻さない。

展示用全体記録の回収は運営側の手順とし、来場者向けの「記録」から全員分を書き出す動線は設けない。新しい認証システムを展示の成立条件にせず、運営用のデータ回収と来場者UIの範囲を分ける。
新runは同じ静的mapと初期の固定晴れ、届け先「おまかせ」から始める。旧runの残り投数・天候材料・固定した場所を引き継がず、新しいmapをその場で生成しない。同runを再開しただけなら、現在の期・材料・Prepared・保存された届け先設定を保つ。

## 9. G3で確認する受け入れ場面

以下の23場面は実装後の確認項目であり、現時点の合格結果ではない。出生時の見た目は採用した展示ビルドで確認し、未採用なら確認済みとして数えない。

1. 初回に目標・本文・方法・場所を選ばず、おまかせの届け先から一操作で一投を始められる。
2. 面の説明を見ても目標が勝手に変わらず、意図欄で選んだ設定だけが確定される。
3. faceIdを目標にした次回、同じ番号の中身が変わったことを読める。系統目標が0/6になっても、保持・変更・そのまま投擲を選べる。
4. 同じpointerの連打・二本指・key repeat・skip・閉じる操作から、二つ目の投擲が発生しない。
5. 過程を再生している最中に次の6面・目標編集・Rollが有効にならない。省略後は同じ終状態と次のPreparedが対応する。
6. 何も操作しなくても、入力・変化・ことばを見た後に次を振れる。読了・カード開封・保存確認を要求しない。
7. 低刺激・消音、小さい横画面でも、6面、選ばれた面、作用点、本文を読み取れる。
8. 当時の庭と現在の庭を混同せず、記録から戻っても同じPreparedを保つ。
9. 保存済み結果の中断、結果不明、カードだけの失敗、保存失敗で、案内と実際の回復が一致する。
10. 来場者交代後、前の目標・方法・自由文・固定届け先・次からの選択・過去runの本文が来場者UIへ現れない。
11. 最初の三つの正常解決投は晴れで、4投目の準備前に新しい期が確定する。取消・欠測・長押し・履歴・演出省略だけで期が進まない。
12. 小雨の中でサイコロの雨・光・風を引いても、天候と局所入力を別々に見分けられる。天候の雨だけで水の目標が一致した表示にならない。
13. 待機中の空や雨粒は動いても、水量・土の湿り・植物段階は変わらない。復帰時に待機時間ぶんの降雨をまとめて追加しない。
14. 旧天候・旧地点での提示を終えてから次の天候・届け先・6面を同時に公開し、過去の記録では当時の空と場所を示す。消音・低刺激設定でも天候名と作用範囲を読める。
15. 土中水200・容量200と、土中水200・容量1,000のセルは異なる水分比で描く。次のPreparedを公開した待機中に、前回ダイスの局所風・追加光・未抽選の水流が残らない。
16. 種が偶然6面にない回、種の範囲が埋まった回、散布側に1セルだけ空く回で説明が一致する。範囲外の空き土を隠さず、全個体が花の境界状態でも同じ庭で投擲と記録を続けられる。
17. 開花cue直前の省略・提示中の中断では、同じ花と保存文へ進み、飛ばした鐘や成長音を鳴らさない。次のPrepared公開後に旧tokenのcallbackを届けても、音・空・焦点は変わらない。
18. 低fpsで複数cue時刻を越えても、同tickに残る主・補助cueを次frameへ保ち、順序と一回だけの発火を守って一斉再生しない。同groupの別個体が先に段階を越えていても、選ばれた個体のcueはその根拠eventのtickを使う。成長アクセントは合計最大1回とし、通常・低刺激・消音・省略・trace消失で同じ確定終状態と保存文になる。

19. Readyで岩陰を選んでも、公開中Preparedの今回の場所・天候・6面・意図は変わらず「次から：岩陰」と読める。次のPreparationStartedで選択が採用され、以後は変更するまで続く。
20. 提示中に選んだ場所は、終状態の表示後に始める次の準備へ反映される。Preparing中のタップ・押し続け・旧画面のcallbackを保留して次へ適用せず、保存とPreparing開始の競合はwriter順と一致する。
21. おまかせの同じ場所の連続、今回の場所で種が候補外の状態をそのまま示す。場所説明や植物詳細を開いただけで選択・意図が変わらず、追加確認なしで振り続けられる。
22. 同じ開始状態・天候・recipe・保存材料で場所だけを変えた開発比較では、実際の作用範囲・土や植物の変化をそれぞれの場所へ描く。場所名や内部IDだけを変えて多様性とせず、領域外の開花も正しい個体と時点に対応する。消音・低刺激でも違いを読める。
