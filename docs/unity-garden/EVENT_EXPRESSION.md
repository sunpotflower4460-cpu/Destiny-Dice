# 起きたことから、庭が分かる表現

ユーザーの「基本説明よりは起きたことで説明・表現する」という指定を、日常の表示の優先順にする。
条件一覧や予測を読む前に、その庭で起きた場所・関わった命・残った変化が伝わるようにする。
生態と抽選の規則、保存形式は `ecology.v8` のまま。表現用の投影から庭を書き換えない。

## 出来事の文を作る根拠

`GardenMoments` は、解決済みの関係イベント・成長イベント・その投の終了状態から短い場面を作る。
例は表示規則を示したもの。実際の庭に根拠がそろった時だけ使う。

| 文の例 | 必要な記録 |
| --- | --- |
| 蜜を補ったデイジーに、花蜂が訪れた。 | 同じセル・同じ種類の `care-nectar` と実消費量が正の `nectar-fed` |
| 藻の育った水辺で、オタマジャクシが食べた。 | 同じセルの実際の `algae-grew` と `algae-eaten` |
| 小虫の減った葉で、スミレが持ち直した。 | 同じセルの実際の `predation` と `recovered` |
| ミミズがほどいた落ち葉の一部が、腐植になった。 | ミミズによる実際の `humus-formed`。養分の文には同じ分解者・セルの `decomposed` も必要 |
| ハッカの地下茎が、隣の土に根づいた。 | `clonal-rooted`。境目の文には保存済みの両側の居場所も必要 |
| この投で蒔かれた種から、育った芽。 | 同じ投・同じ株IDの `SeedPlaced` と成長イベント |

蜜や藻の新しく増えた一単位を、特定の訪問者が食べたと断定しない。
同じ花・水辺で、補充と食事が実際に起きたことを伝える。
存在している住人数だけから、羽化・産卵・定着を作らない。

量0の資源イベントを、食事・移動した養分・散布の成功へ変えない。
一方、株や幼い命が土へ還る記録は、落ち葉の上限で還元量が0でも残す。
花を閉じた株や入れ替わった株へ、今も咲いている花として焦点を当てない。

## 表現の選び方

- 羽化・芽吹き・新しい根・結実だけでなく、弱り・喪失・乾燥・旅立ちも場面にする。
- 同じセルは、同時に起きた関係を含む代表場面へまとめる。
- 日常の訪花・食事・分解・根への養分も扱い、節目がない投を架空の誕生で埋めない。
- 同じ優先度では投数とセルで順を回す。種類・元の場所でも順を固定し、列挙順で表現が揺れないようにする。
- 生態の出来事がなければ、その面が出たことや実際に水を注いだことだけを示す。
  見ていない命・感情・成功は加えない。場所が特定できなければ光の焦点も作らない。

## 普段の画面

- 一投の大きな文は、起きた出来事と「何投目・どの入力・どの居場所」を示す。
  カードの言葉や比較数値より、庭の場面を先に読む。
- 場面の根拠になったセルへ、既存の輪郭の光を合わせる。
  観察の「この出来事の場所を見る」も、選んだ場面のセルを指す。
  選んだ文を大きな表示へ出し、パネルを閉じてその場所を見る。投擲の再生中はこの操作を受け付けない。
  過去の出来事の場合は場所を示し、当時の植物や水辺を現在の庭へ作り直さない。
- 「庭を観察」の初期表示は最近の出来事。居場所ごとに、その時の終了状態の分類で絞る。
  「新しい出来事」「前の出来事」で一件ずつ選び、文と場所の対象を切り替える。
  株や種を特定できる場面では「この株の歩み」「この種の歩み」から、由来・節目・残した命へ移れる。
  同じ場所の別株を混ぜず、保存したIDで親株・種・子株を結ぶ。詳細は[GARDEN_MEMORY](./GARDEN_MEMORY.md)を参照。
  見通し・条件・仕組みは、任意の「見通し・しくみを読む」へ移す。
- 見通しの自然計算は、その詳細を開いた時だけ行う。出来事を眺めたり居場所を絞ったりするだけでは計算しない。
- 記録の通常表示も出来事を中心にする。元のカードの言葉と比較値は詳細表示に残す。
- 図鑑は長い一般説明で始めず、その庭の最近の出来事から始める。種類ごとの条件・役割は参照として残す。
- 保存復帰後の大きな文も、最後の解決済みの出来事から戻す。

## 保存と検証の境界

ライブと履歴は同じ `GardenMoments.Read` を使う。履歴では対象runの最近12投までを復元し、
各投の終了状態を使う。現在の庭から過去の場所や株を推測しない。
表示件数を絞った抜粋であり、すべての現象が起きなかったという意味にはしない。

元の `selectedMessage` や状態ハッシュ、台帳は編集しない。出目・カードの抽選へ戻す処理もない。
解決していない投や別の来場者の記録から、出来事を補わない。

実C#のテストでは、関係が同じセル・種類・株IDで結べること、離れた出来事や0量を結ばないこと、
生息と誕生の区別、負の出来事、閉じた花や入れ替わった株、5つの居場所、保存後の不変性を検証する。
実coordinatorの32投を記録し、最新3投のライブ表現とJSON履歴の文・場所・順序・歩みの入口IDが一致することも照合する。

Unityでの文字の収まり、文と輪郭の場所、低刺激表示、パネルの切替とタッチ/ホイール操作は別途確認する。
