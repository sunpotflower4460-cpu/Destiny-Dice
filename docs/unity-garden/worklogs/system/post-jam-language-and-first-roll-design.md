# ジャム後の設計：日英切替と、最初の一投のガイド

状態: **設計のみ・実装未着手**（2026-11-20）。対象は Unity 版 Destiny Garden。提出済み WebGL、itch.io の掲載・返信、既存の実験アプリ `src/` と凍結プロトコルはこの作業の対象外。

海外の試遊者から寄せられた英語対応と短い操作ガイドの要望に応えつつ、庭を眺めてすぐ振れる、静かな始まりを保つ。[ジャム提出とコメント](https://itch.io/jam/official-unity-game-jam-2026/rate/5359338)・[既存の体験設計](../../EXPERIENCE.md#1-最初の数投で伝えること)を参照。

## 2. 日英対応

- タイトルと設定の双方に `日本語 / English`。初回は日本語端末なら日本語、それ以外は英語を候補（端末言語が得られないときは日本語）。明示切替を最優先にし、アプリの表示設定として保存する。切替に庭の再作成・再起動・再抽選を要求しない。古いセーブで設定が無ければ初期選択規則へ。OS言語変更は明示選択を上書きしない。
- Unity Presentation の小さなローカル辞書を単一入口にする。ユーザーに出す日本語を翻訳キーに使わず、画面・用途を識別する安定IDと、名前付きプレースホルダを使う。起動からオフラインで使える日英セット。欠けたキー／変数不一致はテスト失敗。予期しない欠けは日本語へフォールバックし、ログにキーを残す（画面に内部キーや空欄を出さない）。ゲーム中の翻訳APIは不要。
- 第1段階はタイトル・設定・初回ガイド・投擲と結果・操作ラベル・エラー／確認、次に観察・図鑑・履歴・庭のしおり・オラクル本文と説明。全範囲の見直しが終わるまで「完全英語対応」と表明しない。庭の固有名や詩は直訳より短く自然に。水／風／光／種は Water / Wind / Light / Seed で統一し、色だけに頼らない。
- 保存されるカード・文章・イベントのID、出目、内容の選択／ハッシュはそのまま。構造化事実を描画時に言語化する。保存済みの本人の祈り・庭名・過去の原文は翻訳で上書きしない。安定IDのない既存の保存済み文は原文を表示する。数値の桁・日付・文字折返しは表示だけに適用する。
- 切替で設定パネルを再生成する場合も、投擲、確認、祈り入力に二重発火させない。未確定の文字列は保持するか、IME変換完了まで切替を保留する。画面の生きた状態・公開APIを変える必要が出たら担当間で先に合意する。

## 3. 任意のインタラクティブガイド

目標は「最初の本物の一投を自分で振り、その恵みがどこへ届いたかを見つける」。新規プレイ初回の通常の庭で、読み飛ばせる2つの短い案内。登録、願いの入力、面の選択、目印のタップは必須にしない。

| 状態 | 表示文案（日 / 英） | 動作と遷移 |
|---|---|---|
| 一投前 | サイコロを振って、庭に恵みを届けよう。 / Roll the die to send a blessing to your garden. | 画面端の小さな吹き出しで既存の「振る」を示す。通常ボタンを押すと既存coordinator経路で一投。願いは任意。スキップはガイドだけを閉じ、庭の操作を奪わない。 |
| 最初の結果が確定 | 恵みが届いた場所を見てみよう。 / See where the blessing landed. | 実際に選ばれた面と作用地点を示す。既存の記録から説明し、開花などを保証しない。対象取得不能なら文章だけ。閉じる／続けるで終了。任意の「庭を観察」案内は導線を示すだけで次へ進む条件にしない。 |

- 通常の投擲ボタンと同じ入力経路だけを使う。ガイド専用の出目、練習用の台帳追記、強制カメラ移動、タイマー、追加ロールは作らない。実際の解決（保存済み結果／既存の復旧可能な結果）で次へ。アニメーション終了・音の有無だけで進めない。Reduced Motionでは静的な輪郭＋短文を使う。
- 状態は Presentation の `off / offered / awaitingCommittedResult / resultHint` を目安にし、完了またはスキップのみ表示設定へ保存。再読込では本物の既存セーブを正とし、0投の未完了なら一投案内へ、保存済みなら再投を要求しない。セーブ済みの既存利用者や2つ目以降の庭に初回案内を繰り返さない。
- 「メニュー → 遊び方」から再表示。既存庭では直近の保存済み結果があればそれを例に使い、なければボタン案内のみ。自動投擲なし。画面を閉じる／OSで中断／ブラウザで戻る場合は、ガイドの閉鎖で通常操作に戻り、ゲーム側の中断復帰契約を維持する。

## 4. 受け入れ・配布の条件

| 項目 | 合格証拠 |
|---|---|
| 文案・UI | JA/ENのキー・変数一致と、タイトル、設定、ガイド、結果、エラー、拾い直した祈り／履歴のキャプチャ。日本語の豆腐、英語のはみ出し、色だけの区別がない。本文と字幕で音なしでも理解できる。 |
| 初回・スキップ・復帰 | 新規開始、即スキップ、1投後閉じる、既存庭からの再表示、投擲中の連打／中断／再読込、旧セーブ、別の庭。復元前後のrun ID、投数、出目・保存結果を照合し、重複ロール・再抽選・旧庭消失なし。 |
| 言語切替 | タイトルと庭で双方向切替、再読み込みで維持。切替前後で同じ庭・履歴・祈り原文・保存の内容を比較。IME変換、文字入力中のカメラ操作漏れ、二重発火も確認。 |
| WebGL | **開発用コピー**を1280×720のiframe（itch相当）、ChromeとSafari/WebKitで。初回クリック後の音、無音時の理解、ミュート、再読込・背景復帰、初回カメラ、Windows/日本語IMEまたはmacOS日本語IME、書き出し非表示を実入力確認。公開ジャム版のセーブをテストに使わない。 |
| iPhone | **実機**Safariのタップ・ピンチ、縦横／セーフエリア、スクロール、キーボード・IME、長い英語、消音ON/OFF、ロック／復帰・保存。ネイティブiOSを配布候補に含める段階では同じ主要経路を別記録。エミュレーションやmacOS WebKitのみで実機合格としない。 |
| 回帰と試遊 | Unity EditModeでキー検査・状態遷移・既存の復元／確率不変を照合。初見の英語話者が口頭説明なしで一投し、何が起きたかを言えるかを観察。小標本は感想と課題で記録し、成功率の証明にしない。 |

[公式ジャム規定](https://itch.io/jam/official-unity-game-jam-2026#voting-period)では投票中の掲載ページ説明・画像の調整と、ゲームファイル変更を区別する。コミュニティ投票終了だけを差替え判断に使わない。Unity特別賞審査の予定は12/7まで。審査期間終了・運営規定を再確認し、公開は別承認。新しい検証・配布ビルドは提出SHAと別名・別保管し、公開前に対応する表示ラベル・スクリーンショット・操作案内の版を同時に照合する。音修正は既存の開発版 [#62](https://github.com/sunpotflower4460-cpu/Destiny-Dice/pull/62) を前提に回帰だけ確認し、提出ZIPへ適用しない。

## 5. 実装の引き継ぎと今回の記録

1. Claude Code（見かけ）：`GardenUi*.cs`・`GardenBootstrap`・フォント／レイアウトで辞書、切替、最初の一投の表示。通常ロールと旧UIを基準に1画面ずつ移行する。
2. Codex（仕組み）：既存の結果／記録と保存互換性の検証。もし現行公開APIで不足なら、必要な読み取りデータを先に明記し、[分担ルール](../../PARALLEL_WORK.md)に沿って接続を合意する。まずドメイン・乱数・台帳変更なしで成立させる。
3. 同じ開発ビルドで証拠をそろえてから、日英の案内を見直す。提出版と開発版の機能を混ぜない。

今回の完了はこの設計の記録のみ。提出版／開発ベースのソースと提出ZIPの記録照合、公式掲載・コメント・規定の確認済み。Unityテスト、実機、実プレイ、翻訳の通読検証は未実施。実装・公開承認、審査後の配布は別工程。
