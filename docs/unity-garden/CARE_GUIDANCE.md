# お世話の見通しと、届いた土のその後

`ecology.v8` の庭を読むための表示用の投影を追加する。
ユーザーが、何を補うか・何を待つか・届けた場所で後から何が起きたかを考えられるようにする。
生態・配面・自然シミュレーション・保存形式は変更しない。新しい庭の規則版は作らない。

現在の通常表示は、[起きたことから庭が分かる表現](./EVENT_EXPRESSION.md)を優先する。
本書の見通しと仕組みは、観察の任意の詳細表示から読む。

## 今の困りごとと、保ちたい条件

`CareOutlook.ReadConcerns` は保存済みの状態から、次の観察対象を挙げる。

- 名前の分かった株の乾き・過湿。生長中の株には種類の湿りの範囲と、自然成長が可能な101〜949‰の共通部分を使う。
  開花済みの株には種類の範囲を使う。これは最適な湿りや生育全体の適合度の予測ではない。
- 元気な株にも、今の湿りを保つための注意を示す。水を補い過ぎたり風で乾かし過ぎたりする面が分かる。
- 湿りは戻ったが回復中の株、養分不足の株、蜜の少ない花、実った綿毛の種。
- 空いている土で湿りを待つ種。休眠・季節・空き地など別の条件を待つ種には、その理由を残す。
- 水辺の土の湿りを失ったカエル・トンボの暮らしと、藻が足りないオタマジャクシ。

幼い水生の命、負担のある根、眠る種などの順に優先する。各居場所3件・全体最大15件に絞り、
画面には選んだ居場所の上位3件（全体表示でも3件）を示す。同じ場所の同種の種などの重複はまとめる。
同点はセルと対象IDで決め、植物・種の列挙順で表示が変わらないようにする。

## 公開済みの面を比べる

`CareOutlook.Build` は、実際に公開されている面と保存された中心・現在の天候を使う。

1. 同じ開始状態で、天候だけの40tickを計算する。
2. 公開中の各入力を、実際の `RecipeResolver / Simulation.Resolve` で計算する。
   七の目には実際の増幅済み入力を使う。未公開の面や、出目の乱数を取得しない。
3. 対象ごとに現在の湿り・天候だけの湿り・その面が出た場合の湿りを比べる。

「範囲へ近づく」は、天候だけでは外れている湿りが範囲内へ入るか、同じ側の外れが縮む場合。
範囲内から外れる場合、外れが広がる場合、乾き側から過湿側など反対側へ飛び越す場合は注意する面とする。
乾きから過湿へ移ることを改善とは表示しない。どちらも範囲内なら、湿りの改善とは数えない。
天候だけで範囲へ戻る見込みも、ダイスの寄与と分けて表示する。

同じ入力が2面にある場合は2面として数え、6面・7面の実際の分母を使う。
蜜や綿毛の種には、追加の光・風100以上が届く面の数を示す。
これは到達の見通しであり、分解・訪花・散布・芽吹き・繁殖が起きる確率や予告にはしない。
養分・元気・実り・空き・季節・湿りの履歴や、後の投の働きも必要になる。

計算用の種には一時的なIDだけを使う。外部乱数・ID発行サービス・台帳への書き込みは使わず、
元の状態・公開済みの面・準備の段階を変更しない。結果は表示用で、実際の抽選へ戻さない。

## 恵みが届いた土の、その後

`CareAftercare.Project` は、検証済みの単一runの `HistoryProjector` の出力を読む。
`ecology.care` に記録された土のセルと、後の投の実際の関係イベントを結ぶ。

- 同じセルに届いた最も新しい**前の投**を使う。同じ投の出来事を、その投の「後日」として扱わない。
- 見る範囲は、その接触から12投後まで。隣の区画や、接触記録のない旧庭へ補って結びつけない。
- 種の目覚め、根からの子株、回復・負担、結実、定着・子育て・成長、幼い命の喪失、乾燥、
  還元、居場所の変化を扱う。よい出来事だけを拾わない。
- 履歴の同じ投や同じ関係が重複して入力されても、同じ観察を増やさない。未解決の投は使わない。
- 当時の入力・居場所・区画・投数と、後から記録された観察の文章を保持する。
  居場所のフィルタは、**届けた時の分類**を使う。
- 最新24件まで保持し、観察では最大3件、記録の冒頭では最大4件を表示する。
  他の出来事は従来の各投の記録とジャーナルへ残る。

これは同じ場所で後から起きたことの振り返り。
ほかの投や天候、生き物の働きも関わるため、その一投だけの功績・原因とは表示しない。
新しい達成フラグや、生態へのボーナスは作らない。

## 画面と計算のタイミング

「庭を観察」の「見通し・しくみを読む」に、見通し・今回の面と中心・その後の記録・詳しい観察を表示する。
見通しの自然計算はその詳細を開いた時に行い、同じ開始状態・公開面・天候の間は再利用する。
居場所のフィルタ変更や願いの選択だけで、同じ40tickを繰り返し計算しない。
新しい準備、七の目の追加、復帰で表示の材料が変わった時は更新する。

1つの見通しは天候だけの1回と、重複をまとめた最大7入力の自然計算を使う。
通常の出来事を眺める時や、画面を閉じて振り続ける時には、見通し用の自然計算を行わない。
Unityの型解決・初回表示の応答時間・小画面の長文とスクロールは、Unityで別途確認が必要。

## 検証

実C#のテストで、公開された面と実際の自然計算の一致、天候だけでの回復、七の目と重複面、
過剰な水、休眠や養分不足、幼生の居場所、到達の機会、件数と順序の安定性を確認する。
準備済みJSONからの見通しの再構築、同じセル・前の投・12投の境界・重複・負の出来事・run分離も確認する。
見通しと振り返りを読む/読まない2通りで96投を行い、全状態ハッシュと各投の反応記録を照合する。
v8改修前 `94b3cc7` の初期/96投の既知ハッシュも固定する。
