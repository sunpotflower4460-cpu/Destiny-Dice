# Unityなしで生態の規則を検証する

.NET SDK 8 を用意し、リポジトリのルートで実行:

```sh
dotnet test tools/ecology-check/Ecology.Check.csproj --configuration Release
```

Unityプロジェクト内の **実際の** Domain / Application / Infrastructure と、既存のEditModeテストを直接コンパイルして実行します。
追加のゲーム実装や写経した参照モデルはありません。Unityに依存する診断ログのみ `UnityDebug.cs` で置き換えます。
`PresentationTests.cs` はUnityエンジンが必要なので除外しています。

生態v4〜v8のテストでは有限の養分、受粉から結実までの時間、種の厳密な継承、餌と隠れ場所、植物の回復と世代交代、
腐植への分解収支、土地との相性、つる・地下茎の費用と出生上限、境目の記録、保存復帰を検証します。
v8は5つの環境への届け先、全ての適格なダイス入力、光と風の実効範囲、水の流れ、天候との区別、乾燥の不利益、
意図による出目不変、準備済みの中心と意図の復帰も検証します。
v4の4庭×240投、v5/v6/v7それぞれの384投×2庭×継続/復帰、v8の192投×2庭×継続/準備後の復帰を照合します。
改修前 `ac12b67` の実行で採取した初期状態・24投後のハッシュとも照合し、旧庭の規則を固定しています。
v4は `578f711` の初期状態・48投後、v5は `0171418` の初期状態・96投後、
v6は `0523e33`、v7は `c84fa6f` の初期状態・96投後のハッシュを固定し、保存済みの庭が新規則へ無言で移ることを防ぎます。

お世話の見通しでは、実際の自然計算との一致、過剰な水、天候との区別、休眠や養分不足、七の目と重複面、
準備済みJSONからの再構築を検証します。その後の振り返りは同じセル・前の投・12投の境界・重複・負の出来事・run分離を検証します。
見通しと振り返りを読む/読まない2通りの96投を照合し、v8改修前 `94b3cc7` の初期/96投のハッシュも固定しています。

出来事の表現では、同じセル・種類・株IDの記録を結び、離れた出来事や0量を結ばないこと、
存在と誕生の区別、負の出来事、5つの居場所、閉じた花や入れ替わった株を検証します。
実coordinatorの32投から、最新3投のライブ表現とJSON履歴の文・場所・順序を照合します。

これはUnityのコンパイル、描画、音、入力、WebGLビルドの検証を代替しません。リリース前にはUnity 6000.3.23f1で
全EditModeテストを実行し、WebGLプレイヤーで図鑑・庭を観察のフィルタとスクロール、種の着地と後の芽吹き、
幼虫・さなぎ・オタマジャクシ・ヤゴと水辺の食べもの、定着と移動の観察、新しい住人、
腐植による土の色、つる・地下茎の子株と低い光、相性と待機理由、境目を越えた履歴、
旧v3〜v7ジャーナル復帰と新しい来場者を確認してください。

v8では観察中の各環境を次の届け先に選ぶ→公開済みの面と中心は維持→次の準備から環境内の輪郭へ切替、
という順を確認してください。まだない環境のフォールバック説明、種まきや七の目の実際の作用範囲、
光と風の地形による弱まり、結果と履歴の水・生長の差も確認対象です。録音や長押し時間で自然状態を変えません。

お世話の見通しは観察画面を開いた時に計算し、同じ準備中は再利用します。初回表示の応答時間、
天候だけで戻る場合とダイスの面による変化の区別、6面/7面の分母、当時の居場所で絞ったその後の記録、
画面を閉じたままの連続プレイ、準備と七の目の追加による表示の更新をUnity側で確認してください。

通常の観察は出来事が先に出ること、一投の文と輪郭の場所が合うこと、「最初の出来事の場所を見る」、
詳細表示との往復、元のカードの言葉の詳細表示、図鑑の出来事、保存復帰後の最後の場面を確認してください。
見通しの自然計算は「見通し・しくみを読む」を開いた時だけ行います。低刺激表示では輪郭の拡縮を抑えます。
